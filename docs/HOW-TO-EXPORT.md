# Export a session

This guide covers how a conversation is exported as a file download (HTML,
Markdown, or JSONL) and how the pipeline is wired. Every step is required
unless noted otherwise.

## 1. What the feature does

The `export-session` palette command opens a dialog with three download
options — HTML, Markdown, and JSONL. The selected format is sent to
`POST /api/sessions/:id/export`, and the backend responds with the exported
file as an attachment (`Content-Disposition`), which the frontend saves
through an in-memory object URL.

The Markdown and JSONL outputs are produced entirely inside Livecraft. The
HTML output is produced by Pi itself over RPC (`export_html`), because only
Pi knows how to render its own conversation; the HTML option is disabled when
the connected Pi build does not advertise that command.

## 2. Code ownership

The export pipeline lives in `server/features/export/`:

| File | Responsibility |
|---|---|
| `server/features/export/session-markdown.ts` | Pure Markdown serializer (`sessionToMarkdown`), deterministic given the same messages and `exportedAt` |
| `server/features/export/session-export.ts` | Safe filename builder, format validation, canonicalized JSONL reads, and the `export_html` RPC wrapper with temporary-directory cleanup |

The route is `POST /api/sessions/:id/export` in `server/backend.ts`; it
validates the format, reads the session file or asks Pi for HTML, and responds
with the file plus `Content-Disposition`. The frontend entry points are the
`export-session` command in `src/features/commands/command-registry.ts`, the
download call in `src/api.ts` (`exportSession`), and the picker in
`src/features/dialogs/ExportDialog.tsx`, wired in `src/App.tsx`.

## 3. Output formats

- **Markdown (`.md`)** — the visible conversation as a Markdown document.
  The document title is the session name, and the export instant and working
  directory are recorded in the header. Tool calls render as fenced JSON,
  tool results as fenced output, and thinking as a blockquote.
- **JSONL (`.jsonl`)** — the raw session file bytes, exactly as the manager
  knows them. This is the faithful archive format: it can be re-opened as a
  Pi session.
- **HTML (`.html`)** — rendered by Pi through the `export_html` RPC into a
  backend-controlled temporary directory, then read back and cleaned up.

## 4. Limits and safety rules

- Tool results longer than 10 000 characters are truncated with
  `… (truncated)`.
- Images inside messages are replaced with a `_[image attached]_` placeholder;
  binary data never leaves the session file.
- The HTML output path is generated by the backend inside a `mkdtemp`
  directory and never accepted from the client; anything Pi reports outside
  that directory fails the export.
- The JSONL path is canonicalized with `realpath` before reading and must
  resolve to exactly the session file the manager knows, defeating symlink
  tricks.
- Download filenames strip slashes, quotes, control characters, and unicode
  so `Content-Disposition` can never be used for header injection.
